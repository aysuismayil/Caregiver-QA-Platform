# Test Cases: Booking and Availability

Slot selection, checkout hold, confirmation, rescheduling and cancellation. Columns are explained in the [test case template](../templates/test-case-template.md). Related bug: [BUG-002](../bug-reports/BUG-002-double-booking-race-condition.md).

Example values used: checkout hold 5 minutes, provider response window 12 hours, free cancellation 48 hours or more before the start time.

| ID | Title | Preconditions | Test Data | Steps | Expected Result | Priority | Type | Platform |
|---|---|---|---|---|---|---|---|---|
| TC-BOOK-001 | Book an available slot | Provider has open availability | Sat 10 AM–12 PM, Home Cleaning | Choose the slot, go to checkout, pay | Booking created with status `confirmed`; both sides notified; slot removed from public availability | P0 | Positive | Web/Mobile |
| TC-BOOK-002 | Slot is held during checkout | Provider has one open slot | Same slot, two sessions (User A, User B) | User A starts checkout; User B opens the same provider's calendar | Slot shows as "pending"/unavailable to User B while User A is in checkout (within the hold time) | P0 | Positive | Web |
| TC-BOOK-003 | Hold is released if checkout is abandoned | User starts checkout, doesn't pay | Hold time (example: 5 minutes) | Start checkout, close the tab/app, wait past the hold time | Slot becomes available again | P1 | Positive | Web/Mobile |
